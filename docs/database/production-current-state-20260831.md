## Constraint truth relevant to Phase 1

- `exchange_requests.offered_item_id` and `requested_item_id` currently use `ON DELETE CASCADE`.
- `exchanges.item_a` and `item_b` use default `NO ACTION`, preserving accepted/history rows.
- `exchange_meetups.exchange_id` and `exchange_returns.exchange_id` use `ON DELETE CASCADE` and are unique.
- `collection_items` and `wishlists` are unique on `(user_id,set_number)`.
- `collection_items` and `wishlists` set-number FKs use default `NO ACTION`.
- User-owned collection, wishlist, profile, notification, growth, metric, referral and outbox relationships have the exact delete actions reported by `pg_get_constraintdef`; the capture query is authoritative for the complete list.
- Exchange state still permits legacy states plus `swap_active`: `accepted`, `deposit_pending`, `photos_pending`, `shipping`, `building`, `return_shipping`, `inspection`, `swap_active`, `completed`, `disputed`, `cancelled`.
- Partial unique indexes `uq_active_exchange_item_a` and `uq_active_exchange_item_b` prevent an item from participating in more than one non-closed exchange.

## Index inventory

Production contains 78 public indexes. Important non-constraint indexes include:

- Collection/wishlist: user, set-number and availability indexes.
- Requests/exchanges: participant, responder, item, request and active-item indexes.
- Messaging/notifications: sender, recipient, exchange and user/time indexes.
- Growth: event-name/time, user/time and user/event/time indexes.
- Catalogue: year, theme, active/year/set ordering and trigram indexes for set number, name and theme.
- Profiles: normalized country/city and unique founder/membership-number partial indexes.
- Outbox: pending queue, user and notification-once indexes.
- Product metrics: metric/time and user/time indexes.

Exact `CREATE INDEX` definitions are produced by the evidence query using `pg_indexes.indexdef`.

- `auth.users`: `on_auth_user_created`; `on_auth_user_email_verified`.
- `collection_items`: V1 insert event trigger plus V2 insert/update/delete refresh trigger.
- `wishlists`: V1 insert event trigger plus V2 insert/update/delete refresh trigger.
- `exchange_requests`: notification trigger.
- `member_notifications`: Growth V2 email-outbox trigger.
- `notifications`: older email-outbox trigger.
- `profiles`: founder assignment, location normalization, membership protection and public projection.

## Privilege observations

- Production grants authenticated CRUD only where the browser workflow requires it, while server-only tables are service-role-only.
- Several internal trigger functions still inherit EXECUTE for `anon` and `authenticated`, including `bc_assign_founding_member`, both V1 growth trigger functions, membership protection and referral-code helpers. Trigger-only functions should eventually be explicitly revoked from browser roles.
- `bc_membership_ordinal_seq` currently grants SELECT/UPDATE/USAGE to both browser roles even though assignment is performed by a definer trigger.
- Exact expanded table, sequence and function ACL rows are available through the evidence queries; no privilege normalization is proposed in this checkpoint.

## Reproducibility conclusion

The production current state is now precisely inspectable and fingerprinted, but the repository is **not yet reproducible**. Eighteen applied production migration bodies are absent from `main`: 16 are unrecoverable from available Git objects, while two are recoverable exactly from remote Git branches. A forward-only baseline strategy is required and is designed separately in `database-reconciliation-design-20260831.md`.
