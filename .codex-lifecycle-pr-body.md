## Root cause
The acceptance notification was created correctly in production for Ramya, but the open app only surfaced realtime INSERT alerts for incoming proposals. Exchange lifecycle kinds (`exchange_accepted`, `exchange_declined`, `exchange_cancelled`, `exchange_created`) remained unread in the notification table/badge without a prominent in-app alert. Ramya therefore experienced this as no notification.

Production evidence for the reported acceptance shows an unread `exchange_accepted` notification for Ramya at the exact request acceptance timestamp.

## Fix
- Add a small lifecycle notification client for accepted/declined/cancelled/created exchange events.
- Subscribe only to the signed-in user's notification INSERTs.
- Surface a prominent in-app card immediately for lifecycle updates.
- On login/subscription, recover unread lifecycle notifications so an update is not missed while the app was closed.
- Preserve unread state when the user chooses Not now; mark read only when Open exchanges is selected.
- Route the user to Exchanges.
- Ship the asset through v2/release/service-worker cache and bump release to r5.
- Add regression coverage.

## Safety
- No database/RLS changes.
- No change to exchange state transitions.
- No cross-user notification access.
- Existing durable notifications remain the source of truth.

GO for CI/review; do not merge until checks are green.
